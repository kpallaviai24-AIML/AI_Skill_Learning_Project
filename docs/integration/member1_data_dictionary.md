# Member 1 Data Dictionary and Integration Contract

Project: AI Skill Dependency & Personalised Learning Path Generator

## 1. Purpose

This document describes the datasets and outputs generated by Member 1.

Member 1 is responsible for:
- Skill extraction
- Skill standardisation
- Cross-source skill matching
- Prerequisite relationship preparation
- Dependency graph construction
- Graph validation and evaluation

Members 2 and 3 should use this document when integrating their modules.

## 2. Standardised Skill Catalogue

File:
`outputs/standardised/standardised_skills.csv`

This is the main skill catalogue produced by Member 1.

| Column | Description |
|---|---|
| source | Dataset source: ESCO or O*NET |
| source_skill_id | Original skill identifier from the source |
| skill_name | Standardised display name |
| aliases | Alternative skill names |
| skill_type | Skill classification |
| category | Skill category |
| description | Skill description |
| normalised_name | Normalised skill name for matching |

Important:
- Use `source` and `source_skill_id` together as the skill identifier.
- Do not assume source-specific IDs are globally unique.
- Do not assume normalised skill names are unique.
- The catalogue contains skills from both ESCO and O*NET.

Recommended use:
Member 2 should use this catalogue as the reference list when representing a learner's existing skills and target skills.

| onet_skill_id | O*NET skill identifier |

## 4. Prerequisite Relationships

File:
`outputs/relationships/prerequisite_relationships.csv`

Columns:

| Column | Description |
|---|---|
| prerequisite_skill | Skill that should be learned first |
| dependent_skill | Skill that follows the prerequisite |
| evidence_source | Research source |
| evidence_description | Explanation supporting the relationship |
| confidence | Evidence confidence |
| review_status | Approval or review status |
| review_notes | Additional review information |

Relationship direction:

`prerequisite_skill -> dependent_skill`

Important:
- Only rows with `review_status = approved` are used to build the current dependency graph.
- Pending relationships must not be treated as confirmed prerequisites.
- Relationship endpoints currently use skill names rather than catalogue IDs.
- Name-based matching to the standardised catalogue must be checked for ambiguity.

Current evidence summary:
- 2 approved DOE technical-training relationships.
- 6 pending OpenStax analytical-sequence proposals.

The DOE relationships apply to the rotating-equipment training context. The OpenStax relationships represent suggested chapter progression, not universal prerequisites.

## 6. Dependency Graph

Files:
- `outputs/graphs/skill_dependency_graph.json`
- `outputs/graphs/skill_dependency_graph.graphml`
- `outputs/graphs/graph_validation_report.json`

JSON structure:

- `nodes`: dependency graph skill nodes.
- `edges`: directed relationships.
- `source`: prerequisite skill.
- `target`: dependent skill.
- `evidence_source`: supporting reference.
- `evidence_description`: explanation of the relationship.
- `confidence`: evidence confidence.

Direction:

`source -> target`

The current graph contains:
- 3 nodes
- 2 approved edges
- No cycles
- Valid directed acyclic graph (DAG)

Important:
Graph node IDs currently contain skill names, not source-specific catalogue IDs.

Do not assume graph node IDs directly match `source_skill_id`.

## 7. Graph Validation Rules

The graph builder uses only approved prerequisite relationships.

The validation process checks:
- Directed graph structure
- Cycles
- Topological ordering
- Relationship completeness

A directed acyclic graph can support prerequisite ordering.

## 8. Integration Guidance

### Member 2: Learner Profiling and Skill-Gap Analysis

Recommended input:
`standardised/standardised_skills.csv`

Member 2 should:
1. Represent each learner's existing skills.
2. Represent the learner's target skills.
3. Match learner skills to the standardised catalogue.
4. Calculate missing or insufficient skills.
5. Retain source and source-specific skill identifiers.

Suggested skill reference:

`source + source_skill_id`

### Member 3: Personalised Learning Path Generation

Recommended inputs:
- Member 2's skill-gap output.
- `graphs/skill_dependency_graph.json`
- `graphs/graph_validation_report.json`

Member 3 should:
1. Identify the learner's missing target skills.
2. Use approved graph relationships only.
3. Determine prerequisite ordering.
4. Generate a learning sequence.
5. Handle skills that are not present in the current graph.

The current graph is small, so a learning path may not be available for every target skill.

## 9. Important Limitations

1. Skill matches are not yet human-approved.
2. Six analytical prerequisite proposals remain pending.
3. Two problem-solving proposals remain pending in a separate file.
4. The current graph contains only three nodes and two edges.
5. Graph nodes and prerequisite endpoints use skill names rather than catalogue IDs.
6. The graph is a proof of concept, not a comprehensive dependency database.

## 10. Main Integration Principle

Do not treat similarity as verified equivalence.

Do not treat pending prerequisite proposals as approved.

Use source-specific skill identifiers wherever possible.

Members 2 and 3 should coordinate their input and output schemas before integrating their modules.
